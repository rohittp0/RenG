Kotlin Multiplatform · Public release

You own the context.
RenG draws the frame.

RenG is a Kotlin Multiplatform renderer for an OpenGL context you have already made current. You hand it a FramePlan — a complete definition of on-screen state — and it draws that frame into your framebuffer. The published release draws a basemap from your own map style, plus stickers and geometry painted by your own shader pairs. It does not draw models, terrain, or map labels yet.

Current scope

What the published release draws.

RenG publishes one anonymous Maven coordinate and six targets. It draws into a GL context the caller has already made current, and owns no window, render loop, capture path, or encoder. It performs no network I/O and keeps no cache of its own — transport and store are adapters you inject, and RenG only follows the plan you supply. All six targets are published together; only macosArm64 and linuxX64 are execution-verified against a real GL context, and the KMP guide breaks that down.

It is available as

A common KMP coordinate

Resolve com.rohittp.reng:kmp without credentials.

It draws

Stickers and geometry

PNG stickers anchored to the map or to the screen, and lat/lon-bounded quads painted by your own GLSL ES 3.00 shader pair with your own uniforms and textures.

It does not provide

Models, terrain, or labels

The release draws no GLB models, no terrain, and no map text, and it rejects the globe projection. Asking for a basemap without configuring a style does not fail — it draws none and warns. Basemap drawing is verified on macOS and Linux only.

Public Maven repository

One public coordinate.

Add the public repository through dependencyResolutionManagement and declare the common coordinate with your version property. The KMP guide includes the complete setup.

build.gradle.ktscommonMain
val rengVersion = providers.gradleProperty("rengVersion")

kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("com.rohittp.reng:kmp:${rengVersion.get()}")
        }
    }
}

Current release: available. The browser loads the exact version from public Maven metadata; the readable fallback remains available if metadata cannot be loaded.

Release behavior

Immutable releases, checked before publication.

Every non-documentation push to main releases only after its gates pass. VERSION_NAME is the sole checked-in version input; routine patch advancement requires the newest metadata-listed release's strict completion record, while an intentional upward value bypasses that prior record for partial-release recovery.

01

Build and verify

Every target is compiled or tested, then the coordinate resolves from an isolated local repository.

02

Check exact keys

Each immutable artifact key is checked before upload; an occupied coordinate stops the release.

03

Resolve and complete publicly

Anonymous artifact checks and fresh consumer resolution precede conditional record creation and anonymous verification.

Fail closed by design. A malformed response, transport failure, validation failure, or occupied coordinate stops publication. Releases never overwrite or skip an existing version. Aggregate POM and metadata availability are not completion proof; only the valid immutable completion record is.

Every published release completed. Each passed both exact-source CI jobs and the public workflow, including credential-free six-target resolution and anonymous verification of its immutable completion record. ADR 0013 and the Cycle A design spec and implementation plan remain historical decision records. Version display remains metadata-driven, and this site describes only what the current release does — not what a later one will.
