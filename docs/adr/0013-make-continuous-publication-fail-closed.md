# Make continuous publication fail closed

Every non-documentation push to `main` publishes a release, and manual publication is accepted only from `main`. `VERSION_NAME` is RenG's sole checked-in version input. A stable declaration above every public version requests a deliberate upward release. Otherwise, routine publication selects exactly the next patch after the highest stable public version, but only after that version's aggregate POM returns HTTP 200. The aggregate POM is the completion witness because the aggregate KotlinMultiplatform R2 task depends on all six target R2 publication tasks. Target artifacts and metadata therefore complete before aggregate artifacts and metadata can be published. No separate completion marker is needed.

The completion witness is required only for automatic next-patch advancement. An explicit declaration newer than the public line is the recovery path for a partial release and does not require the previous version to be complete. A missing witness, redirect, transport failure, or any status other than 200 stops automatic advancement. The resolver still probes exactly one selected candidate aggregate POM and stops if it is occupied. It never skips an occupied version. Snapshot declarations, malformed or empty metadata, redirects, transport failures, and unexpected statuses also stop resolution.

A release builds, tests, signs, validates, and resolves from an isolated local repository before it can touch R2. The local publication supplies a manifest of its immutable versioned keys, and each exact key is checked against the authoritative bucket before upload. Any existing key proves that the version is complete, occupied, or partially uploaded, so publication stops without overwriting or deleting anything. Recovery from a partial release is a deliberate upward `VERSION_NAME` change that leaves a version gap. It never reuses or mutates public objects.

The publish job repeats the platform gates needed to stand on its own, including Linux x64 tests, rather than racing a separate CI workflow. After upload it fetches every versioned artifact anonymously. Public metadata consumes the configured retry budget until a valid HTTP 200 document lists the selected version; stale or malformed 200 responses are retried and fail closed after exhaustion. A fresh consumer then resolves the aggregate coordinate for all six targets with no credentials. Cycle A is complete only when this public path succeeds. The first public release is still pending.

This keeps continuous delivery without making an immutable Maven repository depend on optimistic HTTP behavior or atomic multi-artifact upload. Versions may have gaps, but a published coordinate is never replaced, partial state is never hidden, and remote uncertainty always stops the release.
