KMP setup

RenG publishes one public KMP coordinate. Add the repository, declare the dependency, and hand the renderer a GL context you have already made current.

Kotlin Multiplatform Six published targets Apache-2.0 Release available

The published release draws. createRenderer is public API: it takes a FramePlan and draws stickers and consumer-shaded geometry into a GL context the caller has already made current. It does not draw a basemap, models, terrain, or map labels, and it rejects the globe projection.

Version display remains metadata-driven. ADR 0013 and the Cycle A design spec and implementation plan remain historical decision records.

Step 1

Add the repositories.

RenG resolves from the public Maven repository without consumer credentials. RenG's Rentile dependency also resolves Skiko platform artifacts from JetBrains' public Compose repository; limit that repository to its owner group.

settings.gradle.ktsroot project
dependencyResolutionManagement {
    repositories {
        maven("https://maven.rohittp.com")
        mavenCentral()
        google()
        maven("https://maven.pkg.jetbrains.space/public/p/compose/dev") {
            content { includeGroup("org.jetbrains.skiko") }
        }
    }
}

Step 2

Declare the common dependency.

Put the release value in a property. Keeping the declaration property-driven makes dependency updates explicit and keeps the documentation independent of the current public release.

gradle.properties
rengVersion=<version>
build.gradle.ktsshared module
val rengVersion = providers.gradleProperty("rengVersion")

kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("com.rohittp.reng:kmp:${rengVersion.get()}")
        }
    }
}
Current release: available. This page reads the exact version from Maven metadata after loading; if metadata is unavailable, the readable fallback remains available.

Step 3

Draw a frame.

createRenderer adopts the GL context that is already current on the calling thread — RenG never creates one, and never owns your render loop. A FramePlan is a complete definition of on-screen state, so you rebuild it each frame rather than mutating the scene; reusing decoded images, uploaded textures, and compiled programs between frames is RenG's own concern.

KotlincommonMain
// Transport and Store are yours: RenG performs no network I/O and keeps no cache.
val renderer = createRenderer(
    RendererConfiguration(
        outputPixelSize = OutputPixelSize(1920, 1080),
        transport = myTransport,
        store = myStore,
    ),
)

val pin = Placement(
    positionMode = AnchoringMode.MAP, position = Vector3(48.8584, 2.2945, 0.0),
    rotationMode = AnchoringMode.SCREEN, rotation = Vector3(0.0, 0.0, 0.0),
    scaleMode = AnchoringMode.SCREEN, scale = 1.0,
)

val plan = FramePlan(
    frameIndex = 0,
    camera = Camera(48.8584, 2.2945, zoom = 16.0, bearing = 0.0, pitch = 0.0),
    drawBasemap = false, // this release draws no basemap; true only warns and degrades
    stickers = listOf(Sticker(pin, ResourceLocator("https://example.com/pin.png"))),
)

// prepare() suspends; draw() is synchronous and needs the same context current.
renderer.prepare(plan).use { frame ->
    renderer.draw(frame, renderer.mintRenderTarget(FramebufferName(myFramebuffer)))
}
Acquisition and drawing are separate operations. prepare fetches, decodes, and uploads; draw only issues GL calls. queryResources and freeResources report and release what the renderer holds, and close frees everything.

Publication surface

Six published targets.

These targets are the complete publication surface. Apple support is Apple Silicon only; RenG deliberately does not publish iosX64, macosX64, or jvm.

Publication and execution are separate claims, and this table keeps them apart. All six targets ship together in every release, but only macosArm64 and linuxX64 execute RenG's GL code against a real context in continuous integration. Android's host tests run on the JVM with no GL at all, and the rest are compiled rather than executed. Android and iOS bring-up on real devices is a planned cycle that has not happened yet.
