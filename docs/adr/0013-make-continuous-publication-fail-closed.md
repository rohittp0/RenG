# Make continuous publication fail closed

Every non-documentation push to `main` publishes a release, and manual publication is accepted only from `main`. `VERSION_NAME` is RenG's sole checked-in version input. A stable declaration above every public metadata version requests a deliberate upward release. Otherwise, routine publication may select the next patch only when the newest metadata-listed version has a valid completion record. First-release metadata HTTP 404 remains declaration-governed. The selected candidate still receives exactly one aggregate-POM availability probe, and an occupied candidate stops without skipping.

The completion record is immutable JSON at `com/rohittp/reng/kmp/<version>/reng-release-completion-v1.json`. Schema version 1 has exactly four fields: integer `schemaVersion` equal to 1, canonical stable `mavenVersion`, lowercase 40-character `sourceCommitSha`, and lowercase `manifestSha256` over the exact serialized immutable local manifest. Routine advancement requires HTTP 200 and a strict record whose Maven version matches the newest metadata version. A missing, malformed, mismatched, redirected, uncertain, or otherwise unsuccessful record read stops and instructs an explicit upward `VERSION_NAME` recovery. An explicit declaration newer than every public metadata version bypasses the prior record, so a partial release can be abandoned without overwrite, deletion, reuse, or automatic skipping.

A release builds, tests, signs, validates, and resolves from an isolated local repository before it can touch R2. The local publication supplies the immutable manifest, and each exact artifact key is checked against the authoritative bucket before upload. After upload, the workflow verifies every manifest key anonymously, waits for valid aggregate metadata that lists the version, and resolves all six targets in a credential-free public smoke build. Only then does it create the completion record and conditionally put it in R2 with `If-None-Match: *`. An existing record stops the run instead of being replaced. Of the three completion-record stages, only the conditional-write stage receives R2 credentials; local record derivation and the following anonymous retrieval do not. That final stage retries until the exact locally derived record is visible or the budget is exhausted.

The aggregate KotlinMultiplatform R2 task still depends on all six target R2 publication tasks. This ordering reduces partial states, but neither an aggregate POM nor Maven metadata proves release completion. Only the valid completion record does. Any surviving artifact from a failed attempt remains immutable evidence, and recovery is an explicit upward declaration that leaves a version gap.

Cycle A is complete only when the exact merged commit passes both CI jobs and the first public publication reaches and anonymously verifies its completion record. The first public release is still pending.
